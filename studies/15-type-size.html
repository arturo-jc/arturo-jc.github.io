Study 15

Type size: how should the type follow the window?

Every piece of type is sized in drawing units, so it scales with the window as the drawing does. Two things follow. Near the bottom of each layout's range the type is small: in an 1100px window the copy is 13.3px and the stack lines and the copyright about 9px, a little less again with a scrollbar beside them, and on a 320px phone the copy is 13.8px. Zooming in does nothing between about 1100 and 1500px: zoom narrows the window in CSS pixels by the factor it enlarges them, so the copy stays the same size on screen until the page crosses into the narrow layout.

In every option the drawing and the name scale with the window, as now, and so do the seats: where each block sits and how wide its column is. What changes is how every other piece of type (the headings, the projects' names, the copy, the stack lines, the link to the blog and the copyright) relates to them; D changes the breakpoint instead. Type larger than the drawing expects wraps into more lines, and the circuit grows round it, because the layouts are built from the type as measured.

Each option is shown in an 1100px window, the narrowest that gets the wide layout, on 320 and 390px phones, and zoomed to 100, 110, 125 and 150% on a 1366px laptop, cropped to the copy at the size it would be on that screen. The windows and phones scroll inside. At the bottom, a panel mixes the rules, the sizes and the breakpoint, at other window widths and on other laptops.
